# Recog: поддержка Linux + подготовка репо к установке коллегами

## Overview
- Снять привязку recog к одной macOS-машине: системный звук через `parec` (PulseAudio/PipeWire) наравне со ScreenCaptureKit, ASR-устройство `cuda|mps|cpu` по env, сервисы из шаблонов (launchd + `systemd --user`), личные данные и артефакты — из git в конфиг, установка одной командой `./setup.sh`.
- Цель — коллега клонирует репо из внутреннего stash и поднимает полный live-пайплайн (системный звук + микрофон + расширение + web UI + сервисы) без правки исходников; поведение и потребление RAM на существующем Mac не меняются.

## Context (from discovery)
- Ветка `main`, рабочая копия чистая на `BASE_REVISION`. Полный исходный план (контекст, условия сохранения RAM, детали каждого шага, верификация) целиком перенесён ниже в раздел «Детальный план — источник требований».
- Затрагиваются: `recog/live.py`, `screencapture_audio.py`, `recog/asr.py`, `recog/config.py`, `recog/remote_asr.py`, `recog/ws_origin.py`, `recog/copilot_supervisor.py`, `mp4_notes.py`, `meeting_storage.py`, `frontend/server.py`, `recog-service.sh`, `setup_venvs.sh`, requirements, `.env.example`, `.gitignore`, `README.md`, `CLAUDE.md`, `adr/`, тесты.

## Development Approach
- **Testing approach**: Regular (тесты пишутся вместе с кодом в том же коммите).
- **Перед каждой задачей обязательно прочитать одноимённый подраздел в «Детальный план — источник требований» ниже** — там точные сигнатуры, номера строк, обоснования и подводные камни; чеклист здесь — только оглавление.
- Один шаг = один коммит, безопасный для деплоя в одиночку (рефакторинг → перенос → фича). Не смешивать шаги.
- Раздел «Условия сохранения поведения macOS и потребления RAM» — жёсткие ограничения, а не пожелания: MPS/FP16/`_model_lock`/`_mps_autoreleasepool`/частота `_maybe_empty_mps_cache` не трогать, версии ML-стека не обновлять, второй набор аудиобуферов не создавать.
- Никогда не редактировать существующие `.env` / `frontend/.env` / `speakers*.json` пользователя — только `*.example`.
- Сообщения коммитов — английские, imperative subject.

## Детальный план — источник требований

## Context

Recog сегодня работает только на macOS одного человека: системный звук берётся через ScreenCaptureKit (Swift-хелпер `sck_audio_capture`) или BlackHole, ASR выбирает `mps`-или-`cpu` и никогда CUDA (`recog/asr.py:63-65`), сервисы — четыре launchd-plist с захардкоженным `/Users/vkkovalev`, `setup_venvs.sh` требует Homebrew и sibling-checkout `../GigaAM`, в git закоммичены arm64-бинарь `sck_audio_capture` и `speakers*.json` с голосовыми эмбеддингами реальных коллег, дефолты `recog/config.py:159` (Tailscale-URL Z270XX) и `frontend/server.py:1735` (`/opt/homebrew/bin/ffmpeg`) личные. Коллеги по команде (Ubuntu/Arch + macOS) должны склонировать репо из внутреннего stash и поднять полный live-пайплайн без ручной правки исходников.

Решения, принятые с пользователем:
- Полный live-пайплайн на Linux (системный звук + микрофон + KTalk-расширение + web UI + сервисы).
- Системный звук на Linux — `parec` (PulseAudio API; работает и с PipeWire через `pipewire-pulse`), raw float32 mono 16 kHz в stdout — тот же wire-протокол, что у Swift-хелпера → `ScreenCaptureAudio` становится generic subprocess-capture.
- ASR: оба пути — локальный (`cuda > mps > cpu`, env override) и `RECOG_ASR_BACKEND=remote`.
- Copilot supervisor ставится **у всех** (все 4 юнита), но авто-спавн по митингу выключен по умолчанию для новых установок (`RECOG_COPILOT_AUTOSPAWN=0` в `.env.example`); ручной спавн из вебапки и статус-чип работают всегда.
- Личные данные — в конфиг, историю git не переписываем.
- Сервисы на Linux — `systemd --user` с `Restart=always` (сохраняет fail-fast-контракт `_setup_meeting_storage`, сейчас опирающийся на launchd `KeepAlive`).
- На обеих ОС `restart` / `restart-supervisor` сохраняют действующую copilot-сессию; явные Stop / uninstall завершают её. На Linux процессам copilot нужен отдельный от supervisor жизненный цикл (см. шаг 8).
- Подсказки по пакетам: apt (Ubuntu/Debian), pacman (Arch), brew (macOS).

Не входит в объём: перенос репо в stash (делает пользователь), правка `deploy/z270xx/*` (инфра gateway), `tests/e2e/` (остаётся macOS-only за маркером `e2e`), поддержка Windows.

## Условия сохранения поведения macOS и потребления RAM

- На существующем Mac сохраняются выбранный ASR backend, ScreenCaptureKit, четыре постоянных сервиса и текущая частота/объём capture-буферов. Linux-only наблюдение PulseAudio и transient systemd-unit на macOS не создаются. Общий класс заменяет реализацию буфера, не добавляет второй набор аудиоданных.
- При здоровом remote-ASR локальные веса остаются незагруженными; после отказа remote допускается одна ленивая локальная модель, как сейчас. В локальном режиме на Apple Silicon сохраняются MPS, FP16-энкодер, общий `_model_lock`, `_mps_autoreleasepool` и существующая частота `_maybe_empty_mps_cache` (`_MPS_EMPTY_CACHE_EVERY=100`). CUDA→CPU fallback ограничен CUDA и не переводит Mac на CPU.
- Обновление существующего venv не меняет версии ML-стека попутно с переносом на Linux. Для macOS зафиксировать проверенный набор прямых и транзитивных зависимостей Recog в `constraints/macos.txt`; исходные версии для проверки — Python 3.12, torch/torchaudio 2.8.0, numpy 2.3.5, pyobjc-core 12.1. Включать только зависимости Recog, не полный набор посторонних пакетов из общего venv. Применять constraints во всех pip-этапах setup и macOS CI; при несовместимости остановиться с объяснением, не снимать ограничения и не обновлять пакеты автоматически. Отдельную смену этих версий проверять независимо.
- `setup.sh` не создаёт временную CPU/MPS-модель для предзагрузки или проверки кеша. Готовые файлы переиспользуются; недостающие скачиваются и проверяются потоково без десериализации весов. Полный inference-smoke выполняется отдельно от обновления работающего сервиса.
- Перед удалением старого remote URL из дефолтов проверить действующую конфигурацию: на этом Mac обнаружено `RECOG_ASR_BACKEND=remote` без явного `RECOG_ASR_REMOTE_URL`. Пользователь должен записать текущий адрес gateway в `.env` до применения изменения/рестарта. Агент и setup не редактируют существующую `.env`. Проверка пустого URL не запускает ASR и не подменяет remote локальным backend.
- Приёмка требует сравнения памяти macOS до/после по одинаковым сценариям (см. верификацию). Успешный короткий звонок или зелёные unit-тесты сами по себе не подтверждают отсутствие регрессии RAM.

### 3. feat: generic subprocess-capture + PulseAudio-бэкенд
В `recog/system_audio.py`:

- **Restart-политику наследовать нельзя** (`screencapture_audio.py:118-133`): одиночный транзиентный сбой убивает захват навсегда. `_restart_process()` бросает, если ребёнок мёртв через 0.5 с после respawn (ровно то, что делает `parec`, пока перезапускается `pipewire-pulse`), а `except Exception: … break` выходит из потока на первой же такой ошибке — до `max_restarts=5` эта форма отказа не доживает; `self.running` при этом не сбрасывается, `get_chunk()` навсегда отдаёт `None`, `_process_chunk` молча ничего не делает, а `if self.running: return` в `start()` блокирует восстановление на всех следующих митингах до перезапуска сервиса. В meta митинга при этом остаётся `system_audio=True`, а systemd `Restart=always` не помогает — процесс здоров. У Jitsi/Matrix пер-спикерного PCM нет, микс — единственный источник чужой речи. Поэтому: retry с ограниченным backoff (1/2/5/10 с, cap), который **не выходит из цикла, пока `running`**; после исчерпания попыток — сдаться явно (`self._dead = True` + `running = False`), чтобы потребитель это видел, и `recog/live.py` один раз написал отдельный маркер потери системного захвата. Из `_emit_pcm_transition_marker` (`recog/live.py:1369`) можно извлечь только нейтральную запись сообщения с проверкой поколения встречи: напрямую метод не вызывать — он описывает PCM→mixed и приостанавливает refine. Ошибка subprocess-capture не меняет состояние здорового per-speaker PCM/refine.
- `def parec_argv(source: str) -> list[str]`: `["parec", "--raw", "--format=float32le", "--rate=16000", "--channels=1", "--latency-msec=100", f"--device={source}"]`. Флаги проверены на Manjaro + PipeWire (`parec --help`, `pactl 17.0`).
- `def resolve_pulse_monitor_source(env=os.environ) -> str`: непустой `RECOG_PULSE_MONITOR_SOURCE` задаёт фиксированный источник, иначе начальный выбор — **`@DEFAULT_MONITOR@`**. Это имя разрешается в текущий монитор при создании потока и само по себе не гарантирует следование за сменой default sink (см. [выбор конкретного target в PipeWire](https://github.com/PipeWire/pipewire/blob/1.4.7/src/modules/module-protocol-pulse/pulse-server.c#L2041)). Без override захват явно отслеживает изменение `pactl get-default-sink` и переподключает `parec`; источник и наблюдение принадлежат capture, завершаются вместе с ним, запросы имеют timeout. Краткая ошибка `pactl` не обрывает текущий поток: rate-limited лог и повтор. Плановое переподключение не расходует бюджет crash-retry; граница источников явно маркируется, overlap через разрыв не склеивается и старому буферу не присваиваются новые timestamps. При override автопереключение отключено. Без `--device` parec пишет дефолтный *source* (микрофон), поэтому монитор обязателен.
- `def resolve_system_audio_backend(spec, platform=sys.platform, which=shutil.which)`: `"auto"` → `"screencapture"` на darwin, `"pulse"` на linux при наличии `parec` (иначе `RuntimeError` с подсказкой `apt install pulseaudio-utils` / `pacman -S libpulse`); `"screencapture"` вне darwin и `"pulse"` вне linux — понятная ошибка; `"device:<id>"` и `"none"` проходят как есть.

### 5. feat: выбор устройства ASR `RECOG_ASR_DEVICE`
- `recog/config.py`: `RECOG_ASR_DEVICE = os.environ.get("RECOG_ASR_DEVICE", "auto")` — `auto | cuda | mps | cpu`.
